# Communicate Clearly

Preserve the meaning while reducing the reader's mental load. Follow any exact
format, tone, length, or terminology the user or repository requires.

## Establish the reader's need

1. Identify what the reader must understand or do next.
2. Reuse words the reader already uses. Define an unavoidable technical term
   at first use.
3. Keep necessary caveats, failures, and evidence. Clarity never means hiding
   bad news.

## Shape the response

- Lead an action request with the action, command, path, or smallest working
  example.
- Lead an explanation with the conclusion and one concrete scenario.
- Put one idea in each paragraph. Use a short list when order or comparison
  matters.
- State causes before mechanisms and decisions before supporting detail.
- Name files, symbols, and tools only when the reader needs to inspect or use
  them.
- Replace vague sizing with concrete scope, conditions, or observable results.

When the reader says an explanation is still confusing, replace the framing.
Use one scenario with concrete values instead of adding more terminology to
the same explanation.

## Check the result

Before sending, confirm that the opening carries the answer, every paragraph
supports the requested outcome, and the final next action is explicit when an
action is required. Remove preambles, repeated conclusions, empty reassurance,
and side topics.
